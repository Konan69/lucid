# Workbook file publication

Model requirement: a real model and the proof-owned disposable Computer. Set `VIVID_VERIFY_KEY_FILE` with model and Boat credentials. Rehearsal cannot prove this feature.

Run Launch, Doctor, `verify feature files <run>`, `verify browser files <run>`, then Cleanup on an unchanged commit. The browser recipe creates its own workbook through the composer.

The model generates a two-sheet XLSX on the Computer with known literal cells and a formula, saves its original bytes as base64 for independent read-back, calls `inspect_file`, reviews its native PNG and typed cell coverage, then calls `publish_file`. A second turn changes Budget B2 and publishes the same title as a new version. Public GetArtifact must retain the server's inspection, matching review digest and tool identity. Output and editable source downloads must equal the Computer bytes exactly. Preview bytes must be PNG and match their digest. Downloading the old version again after revision must return its original bytes.

Read `files/proof.json`, the versioned artifact RPC receipts, downloaded files, history and verdict. The cell read-back covers A1:E5 on up to ten worksheets, names skipped sheets and reports each included sheet's declared used range. Nonempty cells include coordinates, formula text and cached values. Cell text is capped at 200 characters with a truncation flag. Missing formula caches remain null. The read-back does not recalculate formulas or prove cells outside those rectangles. LibreOffice renders a separate first-page preview without changing the captured workbook.

The browser opens the existing Artifact viewer, waits for its first-page PNG to load, captures the view and reloads the Thread. Web and phone already use the retained PNG and offer the original file for download or sharing. Full sheet browsing, in-app XLSX editing and showing machine-readable coverage in the viewer remain Follow-ups for the client owner. Native phone behavior requires a phone run and is not proved by this recipe.
