# Runtime boundaries

The chosen proof stack runs `apps/server/src/main.ts` unchanged, the web client, and one celld
Person cell with a native Pi Durable Harness over Durable Object SQLite. Product PostgreSQL remains a disposable labelled container. Pi's `onWake`/alarm pattern drives durable work;
celld owns activation, ownership, and idle lifecycle.

The launcher source packages the shipped Worker with celld 0.6.2, supplies a disposable MinIO
bucket and starts two native nodes. It has not yet passed a real Launch or product journey.
Require native terminal waiting, abort, Notes, pictures and state-link reconnect after an owner
move through the real product. Doctor establishes readiness and empty Person activation, not
model behavior or recovery. Read [native cell controls](cells.md) before those proofs.

Only model credentials are read from development key sources. Launch never imports application database URLs, Computer identities or production service credentials. Synthetic auth/Google configuration and a fresh VAPID pair belong to the disposable instance. Boat and Photon adapters remain explicitly unconfigured. Launch owns a disposable Executor beta.23 with a private Verify Pulse catalogue and loopback callbacks. The Watch recipe connects that Integration through real Connect. No Computer, Google login, channel delivery or push delivery is proved. Failures at these external boundaries remain failures. A connected disposable authority is required before those features can pass.

The server title model requires OPENROUTER_API_KEY even when the Pi model is rehearsal. Explicit provider environment variables can supplement the private key file. A failed title call logs `Thread title generation failed` after settlement. This failure does not change the settled Run. Record these failures separately from the Watch proof. `VIVID_VERIFY_MODEL` selects the shipped model provider. Without an explicit choice a present key selects a real provider. `rehearsal/script` is explicit opt-in and verdicts say plumbing-only. It never proves model behaviour.

Browser recipes are per feature. Missing recipes fail with no browser recipe. Document proof checks the rendered tool-card button and expanded list item. At this head the web has no GetArtifact caller or Artifact viewer, so opening/editing its body is blocked. The HTTP document recipe separately drives create, revise, read and both immutable versions through public product tools and RPC.

The [desktop recipe](../features/desktop.md) adds the actual Linux Electron app on Xvfb to this same disposable server. It proves email sign-in, outbound Google handoff/Cancel, device connectivity and model browser control. A native egress WebSocket upgrade is recorded separately; Routing still needs a disposable running Person Computer. Google grant/session trade still needs real OAuth authority. Windows/macOS native and packaged behavior need their own OS runs.
