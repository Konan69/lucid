# Upstream suite coverage

This is a behavioral coverage map for the Pi Durable → Vercel AI SDK bridge, not a claim that unmodified upstream suites execute against interchangeable APIs. Ports retain the upstream assertion that applies to this public seam; rows explicitly identify adaptations (HTTP instead of WebSocket, Pi receipts instead of Flue offsets). Private upstream implementation assertions are excluded once per file. Intentional boundary differences are marked not applicable, including refused attachments, append-only history and final-only tool output; missing supported behavior remains a gap.

Source snapshots: AI SDK `7c41e41`; Pi `28dcce2`; Cloudflare Agents `2f3176b`; Flue `832ad2e`. Installed `ai@7.0.127`, `@ai-sdk/react@4.0.130`, and Pi Durable `1.0.4` source controls API and protocol behavior when the reference differs. The Pi checkout's 23 published storage cases match the installed runner's case names. Provider adapters, the SDK JSON/SSE parser, React rendering/store mechanics, Cloudflare platform machinery and Flue runtime ownership APIs are not replaced here.

`ported` means the cited local test proves the applicable behavior. `gap` cites an assertion retained as `it.fails` for supported behavior. Retained-step reconnect is proven through `resumable()` in the integrated core suite. `owned by durable-core` records implementation-specific projection behavior outside the upstream port. `not applicable` states why the behavior cannot enter the library's supported seam or concerns a different API.

Case names include their upstream describe context to disambiguate repeated titles. Parameterized declarations retain their upstream name template; the evidence identifies relevant variants. Counts are source test declarations/table rows, not expanded upstream parameter combinations or number of local tests. One local test may cover several upstream assertions. Only applicable declarations and explicit boundary decisions enter these counts; omitted private cases are outside the denominator.
