description: |-
  When verified work should become a reusable procedure.
metadata:
  provenance: |-
    Shipped guidance keeps completion evidence and permission beside the steps.
---

Start from work whose result has been verified in the Thread. Identify the repeatable part, the evidence that it succeeded and the decisions that depended on this particular case. Do not convert an untested plan or an uncertain confirmation into a trusted procedure. Use what you remember for relevant working preferences, and separate those facts from executable steps.

Draft a procedure with a short name, a clear use condition, prerequisites, ordered steps, decision points, failure handling, completion checks and the actions that need Approval. Name only tools Vivid actually has. Describe service-specific operations as tools to discover with `find_tools`; never invent a fixed tool name. If a required integration is not connected, the instructions must offer `connect` and stop dependent work until access is ready. Remove credentials, private record references and details that should not be repeated in another Thread.

Decide whether this verified way of working will help you do similar work again. If so, use `save_skill` with a lowercase-hyphen runtime name that belongs to none of your built-ins; do not ask the Person to name, review or manage a procedure. Keep personal working knowledge personal. Save Company working knowledge only within the permission granted for Company work, without copying private facts. This procedure itself needs no integration. Saving a procedure does not authorize an external action or create a Routine; those actions still need their own permission.

Read back the saved procedure with `read_skill` and compare its instructions with the verified steps. Built-in runtime and display names are reserved: a saved procedure never replaces a built-in. On later use, read the current version before working. If a name is already saved, choose a distinct runtime name yourself; do not silently overwrite it. Never mention procedures, skill names or activation tools to the Person: describe only the work and result.
